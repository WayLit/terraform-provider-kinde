# Migrate to the official Kinde Go SDK

Status: design approved 2026-10-08, pending spec review.

## Goal

Replace `github.com/nxt-fwd/kinde-go` v0.0.8 with Kinde's official SDK,
`github.com/kinde-oss/kinde-go`. The old library has had no commits since
2025-04-01. The official SDK (v0.3.0, MIT) is generated by ogen from Kinde's
OpenAPI spec and is actively maintained.

Every existing resource and data source keeps working. The work is done when
the provider builds and the unit tests, plus acceptance tests run against a
fake Kinde, pass in CI.

## Context and scope

- The provider will be consumed from Pulumi HCL ("Any HCL Module"). That
  affects publishing, not this design.
- Nothing yet depends on the current schema, so the schema may change where
  noted in section 3.
- Out of scope:
  - renaming the module path and registry namespace to `waylit`;
  - release signing and registry publishing (a separate piece of work);
  - a Pulumi HCL smoke test, which needs a published release;
  - tests against a live Kinde tenant.

## Official SDK facts that shape the design

- It has an equivalent for every endpoint the provider calls.
- Declared 4xx and 429 responses come back as typed results with `err == nil`.
  Undeclared statuses, including 404 on most endpoints, come back as an error
  wrapping `validate.UnexpectedStatusCodeError` and discard the response body.
- `kinde.NewManagementAPI` fails every call unless JWKS token validation is
  enabled, and it drops an error from `GetClient`.
- `GetConnections` and `GetApplicationConnections` decode every item as empty.
  The spec wraps each item in an envelope the API does not send (upstream
  issue #53, PR #63).
- `CreatePermission` returns no ID. The user type has no `updated_on`.
- Decoding is strict: a `null` in a non-nullable `OptBool` or `OptInt` fails
  the whole response, and enum values are validated.
- Optional fields are `OptX` and `OptNilX`. Unset fields are omitted; set
  fields are sent, including `""` and `false`.
- It requires Go 1.24.4 or newer.
- It is regenerated from Kinde's live, unpinned spec, so 0.x releases can
  rename types.
- The package also contains a generated server: `NewServer`, `Handler`, and
  `UnimplementedHandler`.

## 1. The `internal/kindeapi` adapter

Resources talk only to `*kindeapi.Client`, never to the generated SDK.

### Construction

- `kindeapi.New(Config{Domain, Audience, ClientID, ClientSecret})`, falling
  back to `KINDE_DOMAIN`, `KINDE_AUDIENCE`, `KINDE_CLIENT_ID`, and
  `KINDE_CLIENT_SECRET`. `KINDE_SCOPES` is no longer read.
- `Audience` defaults to `<domain>/api`.
- Tokens come from `golang.org/x/oauth2/clientcredentials`, posting to
  `<domain>/oauth2/token` with `audience` as an endpoint parameter. The token
  source caches and refreshes tokens.
- The client is `management_api.NewClient(domain, securitySource, WithClient(httpClient))`,
  where the security source returns the current token. `kinde.NewManagementAPI`
  is not used.
- The provider's `Configure` checks credentials by fetching a token instead
  of listing users, so apps without `read:users` can use the provider.

### One method per endpoint

The adapter exposes one method per endpoint the provider uses (about 45), for
example:

```go
func (c *Client) GetRole(ctx context.Context, id string) (*mgmt.GetRoleResponse, error)
```

Each method is a one-line wrapper around a generic `call[T]` helper. Methods
return the SDK's types; the adapter does not define its own domain types,
except for the raw connection-list fallback. All SDK coupling lives in this
package, so an SDK rename breaks the build in one place.

### Errors

An HTTP round tripper under the SDK records the status and body of every
non-2xx response, keyed by the call's context. `call[T]` returns the result
when it is the success type `T`. Otherwise, or when the SDK returns an error,
it returns `*APIError{StatusCode, Code, Message}` built from the recorded
response.

- `kindeapi.IsNotFound(err)` is true for HTTP 404. It is also true for any
  400 code that Kinde's spec documents for a missing ID; each such code is
  listed in the adapter with a reference to the spec.
- `kindeapi.HasCode(err, code)` matches an error code, such as
  `USER_NOT_IN_ORGANIZATION`.

The same round tripper retries 429 responses up to 3 times. It waits for
`Retry-After` when present (capped at 60 seconds), otherwise 1, 2, then 4
seconds, and stops early if the context is cancelled. Retrying is safe
because a 429 means Kinde did not process the request.

### Lists and workarounds

- List methods return every page: `next_token` for users, permissions, and
  role permissions; `starting_after` with `has_more` for connections and
  identities.
- `ListConnections` and `ListApplicationConnections` call the API directly
  and decode the JSON shape the API actually returns. A comment links
  upstream PR #63; remove the fallback once a release includes the fix.
- `internal/provider/pagination.go` is deleted.
- Phone parsing for phone identities moves from the old library into the
  adapter's `CreateUserIdentity`.

## 2. Resource changes

- Each resource and data source stores a `*kindeapi.Client` from
  `Configure`. The raw `GET /api/v1/roles/{id}` and
  `DELETE /api/v1/organizations/{code}/users/{uid}` calls become adapter
  methods.
- `Read` calls `resp.State.RemoveResource` when `kindeapi.IsNotFound(err)`.
  `Delete` treats not-found as success.
- The membership resources (`kinde_application_connection`,
  `kinde_permission`, `kinde_user_role`) keep their list-scan reads, using
  the all-pages list methods.
- `kinde_user_role` replaces its error-text match with
  `kindeapi.HasCode(err, "USER_NOT_IN_ORGANIZATION")`.
- Two helpers in `internal/provider` map values:
  - `OptString` to `types.String`: unset becomes null.
  - `types.String` to `OptString`: null or unknown becomes unset, and a known
    `""` is sent as `""`.
- The built-in connection strategy names used by `kinde_connections` become
  local constants.

## 3. Schema changes

Resource names, IDs, and import formats stay the same. No resources are
added.

| Resource | Change | Reason |
|---|---|---|
| `kinde_organization` | `theme_code` reads Kinde's theme code and is validated at plan time against the SDK's enum | It is currently filled from `color_scheme` |
| `kinde_organization` | Color attributes stay hex strings; the adapter sends and reads the hex form | The SDK models colors as raw/hex/hsl objects |
| `kinde_role` | Changing `key` updates the role in place | Key changes are never sent today, so the plan never converges |
| `kinde_user` | Remove `updated_on` | The SDK does not return it |
| `kinde_user` | `organization_code` takes effect on create | The old library sent it under the wrong field name |
| `kinde_application` | Read `logout_uris` and `redirect_uris` from Kinde | Drift becomes visible and the URIs can be cleared |
| `kinde_application` | `logout_uris` and `redirect_uris` become sets | Order is not meaningful and the API does not guarantee it |
| `kinde_api` | Populate `is_management_api` | It is declared but never set |
| `kinde_connections` | Return all connections | It currently stops at 10 |
| all | Store `created_on` as Kinde returns it | No existing state needs the old formats |
| provider | `audience` defaults to `<domain>/api` | Nearly every configuration sets this value |
| provider | Mark `client_secret` as sensitive | It is not marked today |

`kinde_role.description` stays required: the constraint comes from the API's
behavior, not the SDK.

## 4. Testing

### Adapter unit tests

These live in `internal/kindeapi` and use an `httptest` server:

- the token request sends `audience`, and tokens are cached until expiry;
- typed 400, 403, and 429 results, typed 404s, and undeclared 404 and 500
  responses all become `*APIError` with the right status and code;
- a 429 is retried after `Retry-After`, then succeeds or gives up;
- both pagination styles return every page;
- the connection-list fallback decodes the API's real shape;
- phone parsing.

### Provider unit tests

- `role_resource_internal_test.go` is rewritten against the fake.
- A table-driven test checks that `Read` removes each resource from state on
  not-found.

### Fake Kinde: `internal/kindefake`

An in-memory, stateful fake built on the SDK's generated server. It embeds
`UnimplementedHandler` and implements only the endpoints the provider calls.

- Roles, users, identities, applications, organizations, connections,
  permissions, and APIs are held in maps.
- It serves `/oauth2/token`.
- It serves the two connection lists in the API's real shape, ahead of the
  generated router.
- It returns Kinde's documented error codes, including not-found and
  `USER_NOT_IN_ORGANIZATION`.
- Test hooks inject 429 responses and delete objects out of band.

### Acceptance tests

The acceptance tests run against the fake on every pull request and on pushes
to `main`. Each test starts a fake and configures the provider with its URL;
no secrets are needed.

The existing tests are updated for section 3. New coverage:

- for each resource, a step that deletes the object out of band and expects
  a plan that recreates it;
- in-place updates of `kinde_role.key`, and of
  `kinde_application.logout_uris` and `redirect_uris`.

The disabled `test` job in `.github/workflows/test.yml` (`if: false`, matrix
Terraform 1.0 to 1.4) is replaced by a job that runs the acceptance tests
with the current Terraform and the current OpenTofu. OpenTofu runs through
`TF_ACC_TERRAFORM_PATH`; how it gets installed depends on the Actions
allowlist.

There is no live-tenant job. The fake encodes our reading of Kinde's spec,
the same spec the SDK is generated from, so CI cannot catch places where the
spec and the live API disagree. That risk is accepted.

## 5. Dependencies and housekeeping

- `go.mod`:
  - remove `github.com/nxt-fwd/kinde-go`;
  - add `github.com/kinde-oss/kinde-go` v0.3.0, `golang.org/x/oauth2`, and
    `github.com/hashicorp/terraform-plugin-framework-validators`;
  - add `github.com/nyaruka/phonenumbers`, which the ported phone parsing
    uses;
  - raise the `go` directive to at least 1.24.4.
- `renovate.json`: point the kinde-go rule at `github.com/kinde-oss/kinde-go`
  and keep `automerge: false`. Its 0.x releases can rename types, and the
  fake shares the SDK's spec, so CI cannot catch API changes.
- Regenerate the registry docs with `go generate ./...`; CI checks the diff.

## Risks

- **The spec and the live API can disagree, and CI won't catch it.** These
  mismatches surface only in real use. This is accepted (see section 4).
- **SDK updates can rename types.** The coupling is contained in
  `internal/kindeapi`, and Renovate requires a manual review.
- **The error codes in the fake follow Kinde's documentation.** If the live
  API returns different codes, `IsNotFound` and `HasCode` may misclassify an
  error. To limit this, `IsNotFound` relies mainly on the HTTP status.
